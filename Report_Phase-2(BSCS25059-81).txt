PHASE 2 REPORT - AI LOGIC & ARCHITECTURE
Project: Shopy - E-Commerce Conversational Database Assistant
Course: CS-254 Database Systems (Spring 2026)
================================================================================

STATUS: COMPLETE

1) What we built
- A true text-to-SQL pipeline that converts natural-language questions into
  SQL SELECT queries, executes them safely on the live MySQL database, and
  returns a plain-English answer.
- Core implementation is in langchain_pipeline.py and is wired into the
  /api/ai/chat endpoint in app.py.

2) LLM provider and configuration
- Provider: OpenRouter via LangChain ChatOpenAI (langchain-openai).
- API key: OPENROUTER_API_KEY (required).
- Model failover: tries multiple models in priority order; skips temporary
  errors (rate limit, timeouts, 5xx) and falls back automatically.
- SQL generation temperature = 0.0 for deterministic queries.
- Answer synthesis temperature = 0.2 for concise, readable responses.

3) Metadata injection (schema awareness)
- The pipeline loads live schema info using SQLDatabase.get_table_info().
- Only approved tables are included to keep the prompt focused:
  users, categories, products, product_images, discount_codes, addresses,
  orders, order_items, cart, wishlists, reviews, ai_chat_history,
  notifications, payments, shipments.
- Schema info is cached (TTL) to reduce repeated introspection overhead.

4) Query generation and validation (Phase 2 + Phase 3 alignment)
- System rules enforce a single SELECT query, no markdown, no comments.
- Generated SQL is stripped, validated, and blocked if:
  - It does not start with SELECT.
  - It contains destructive keywords (DROP, DELETE, UPDATE, etc.).
  - It contains multiple statements.
- Non-aggregate queries get an automatic LIMIT for safety.
- If execution fails, the model is asked to repair the SQL once.

5) Safe execution (read-only access)
- SQLAlchemy URI is built with READ_DB_USER/READ_DB_PASSWORD.
- READ_DB_USER cannot be root; the pipeline raises an error if it is.

6) Answer synthesis and output format
- The SQL result is summarized by the LLM into a plain-English answer.
- The endpoint returns three fields for the UI:
  - query_ran: the executed SQL
  - db_output: raw result snapshot
  - answer: final response

7) Reliability fallback (context-based)
- If the SQL pipeline degrades, app.py falls back to ask_sage_with_context()
  which uses prepared query packs from prompts.py to keep the assistant
  responsive.

8) Security layer touchpoints used by Phase 2
- Layer 2 (input blocklist) is enforced before the LLM call in app.py.
- Layer 4 (output validation) runs before the response is shown.

Key files
- langchain_pipeline.py (text-to-SQL pipeline)
- app.py (API route: /api/ai/chat)
- prompts.py (fallback context responder)
- security.py (input/output validation)
- requirements.txt (langchain, langchain-community, langchain-openai, sqlalchemy)
